# 公开文档站路由入口

`skill-family-docs-quickstart` 根据使用者当前描述的目标任务，立即选定唯一对应的技能，并通过宿主技能加载机制在同一轮继续执行，不在自身正文中重复实现具体步骤，也不只返回一句技能名就提前结束。

| 使用者意图 | 直达技能与边界 |
| --- | --- |
| 了解能力分工或不确定从哪里入手 | `skill-family-docs-help` |
| 检查环境就绪状态或首次接入文档站 | `skill-family-docs-setup`（先零写入诊断并展示精确计划，获批后再写入配置） |
| 首次建站、随代码变动增量更新、整篇改写或纯重新渲染 | `skill-family-docs-build-site`（“只重新渲染”时仅重建产物，不改正文与覆盖锁） |
| 发版前验收、检查 `-site` 仓库命名与显式 Pages 入口/死链/多视口溢出/泄漏/过时限制词或读取共同证明 | `skill-family-docs-check-site`（全程只读，发现问题只定位不自动改稿或篡改锁） |

## 路由与授权边界

- 任务跨多个阶段时，先进入当前满足前置条件的首个阶段技能（如未接入先走 `setup`）；仅在用户明确授权覆盖后续阶段且前置条件已达成时，才衔接下一个技能。
- 目标技能全权承担参数检查、写入边界与验收结论；`quickstart` 不擅自放大只读请求的权限，也不隐藏目标技能报出的阻塞原因。
- 诊断请求在计划获批前不得写入任何文件；只读门禁不得自动转为重写文档；“只重新渲染”不得扩大为刷新内容或更新 `site-coverage-lock.json`。
