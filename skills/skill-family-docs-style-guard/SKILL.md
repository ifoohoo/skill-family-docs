# 中文知识站拟稿与审校

起草、内容刷新或显式整篇重写时，用随技能分发的 `scripts/expression-outbound.mjs` 调用安装者选定的 OpenAI 兼容服务拟稿。宿主负责组织材料、审核大纲、顺序核收各节和全文；模型只产出候选。只读审校可以定位事实、理解和表达问题，但不调用模型改稿，也不据此宣称拟稿流程已完成。

## 先读全文，明确读者与事实

读取 `references/writing.md`，看完本次文稿及直接事实来源。记录懂主题的编辑角色、目标读者及允许的前置知识、读完要完成的判断或动作，再清点章节、事实、条件、例外、限制强度、数字单位、引用、代码、图表与操作步骤。

区分可调整的自然语言与必须保留的机器身份。普通标题、首段和短句可以改写；版本来源、命令、配置字段、状态、链接、页面 ID、URL 和已有稳定锚点必须逐项核对。不得把 quickstart 改成 setup 等不同入口，也不能只数命令或改字数量。材料不足时补齐事实或缩短内容，不用占位段落填满页面。本地源版本不等于已发布或可安装版本；站点版本仍从 `public-release.json` 已声明的来源取得。

选一条主要使用场景，沿同一路径讲清适用条件、必要输入、操作入口、预期结果和失败恢复。架构解释只补完成任务或定位故障需要的职责、流向和限制依据。命令全集放参考页，任务页在真正需要时才引入。普通内容刷新保留 `pages.json` 的 ID、标题、分组、顺序、`productKind`、模板和输出路径；判断读者行为没有变化且原文仍符合目标时保留原文，并说明核对依据。

## 先审核大纲，再顺序拟稿

通过同一个脚本和 `--context` 提供写作任务，不另建阶段状态或配置文件体系。首次请求的 `--input` 是完整且已纠正失效事实的材料；上下文说明角色、读者、阅读任务、用户裁决，以及“只生成大纲”的范围。要求候选大纲说明读者问题、各节目的、材料去向、先后依赖和图表位置。

宿主比较大纲与全文，纠正遗漏、无依据扩展、条件弱化和错误先后关系，另存审核大纲。先把用户最新裁决落实到材料和大纲，再拟正文；不一边保留旧规则，一边用附加提示掩盖冲突。已有且仍获认可的大纲可以沿用，不无故另起。

按完整问题或小节顺序调用。每次 `--input` 只提供当前完整语义单元及必要事实上下文；`--context` 包含角色、读者、阅读任务、审核大纲、当前写作范围、用户裁决和已核对接受的前文。第一节写明没有前文。短文传全部接受前文；长文传上一节全文和更早内容的覆盖摘要，补回本节依赖的定义。前文用于衔接，不能替代当前事实来源；待审候选不能作为下一节前文。不要按固定字数、锚点或表格前后机械切段，也不要并行生成相互依赖的各节。

## 接受每节，再通读全文

读取 `references/revision.md` 与 `references/readability.md`。每节拟稿后，对照原材料和候选集中核对事实与因果、条件与例外、限制强度、数字单位、版本和入口身份、引用来源、角色与对象归属、图表、代码、链接和稳定锚点。再检查首次定义、段间衔接、重复和表格中的长论证。

有明确问题时，在当前材料和 `--context` 中给出集中意见，经同一个脚本另产候选，或由宿主作有依据的最小校订。连续两次同类错误时停止原样重试，先检查大纲、材料范围和最新裁决是否冲突。保留原稿、每次候选和接受稿，说明校订依据；脚本成功只表示候选已产生，不等于语义通过。候选与原文相同或判断无需改写时，核对是否确已符合任务，再决定保留原文，不强行制造修改。

只把接受稿顺序拼接。通读全文，核对原事实覆盖、图文关系、代码、引用和导航；检查分节是否造成重复、指代断开、定义过晚或结论扩大。逐图核对标签、箭头、分组、案例身份及正文挂接位置。图源缺失或图内信息不能识别时，记录具体缺口，不能以文件存在冒充图文核对。无变化图示保留时说明信息核对与无需调整的理由。

让声明的目标读者沿主要场景冷读，只给目标页和已声明前提。记录不知道输入什么、找不到入口、条件不明或无法判断结果的具体卡点并修正。确定性检测通过只表示没有命中硬禁，不能代替事实、冷读或图文核对。完成上述核收后，由 render-site 的既有写路径把接受稿写入 `site.dir`；原稿与候选另存于指定文稿文件。

新格式的 Markdown 不写一级标题，页面 `title` 由 `pages.json` 生成。二至四级标题可在末尾声明 `{#id}` 稳定锚点；提示词使用 `prompt` 代码块，备注只用 `NOTE`、`TIP` 或 `WARNING`。正文不输入原始 HTML、MDX、样式或脚本。

## 服务配置与调用

首次外发前向用户说明：文稿与写作上下文将发送到其配置的 endpoint，本技能不承诺该服务的留存或训练策略。提示由宿主完成，脚本没有交互能力；已有授权不逐次重复确认。发送前移除不在公开材料范围的内容，凭据不进入文稿或上下文。

安装者通过 `SKILL_FAMILY_DOCS_ENDPOINT`、`SKILL_FAMILY_DOCS_MODEL` 和 `SKILL_FAMILY_DOCS_CREDENTIAL_ENV` 三项环境变量选择 OpenAI 兼容服务、模型及凭据来源。第三项的值是存放 key 的环境变量名，凭据值只从该名称对应的进程环境读取，不用命令行传值，也不读写凭据文件。服务不绑定具体模型。

使用统一脚本 `scripts/expression-outbound.mjs` 执行拟稿流程，从技能根目录运行，输入与上下文路径按当前工作目录解析。完整命令如下：

```bash
node scripts/expression-outbound.mjs --input 材料.md --context 上下文.md --output /绝对仓外路径/unit.candidate.md --timeout-ms 180000
```

`--output` 必须为仓外绝对路径，通常使用系统临时目录；每次调用应指定新候选路径，保留原稿与历次候选。候选输出仅创建新文件，已有文件或链接将被拒绝，不覆盖原稿或历次候选。可选参数 `--endpoint`、`--model`、`--credential-env` 用于覆盖环境变量配置，但凭据参数仍仅支持环境变量名。`--timeout-ms` 为单次请求超时时间，默认 60000 毫秒，可按单元需求显式调整，超时后停止且不自动重试。

脚本仅输出候选文稿与固定状态 JSON，没有接受候选的权限，也不判风格或语义。状态字段为 `candidate-produced`（产出待审候选）、`not-configured`（缺配置）或 `failed`（调用失败）。失败原因按 `reasonClass` 分类，包括 HTTP 错误、超时、不可解析、截断等。诊断信息仅记录状态、原因类、退出码与必要路径，不回放正文、凭据、授权头或认证配置；原稿、候选与接受稿仅保存至指定文稿文件。

## 完成与失败边界

当配置缺失、服务调用失败或候选未被接受时，原稿必须保留，明确报告“表达优化未完成”，并说明具体原因：配置缺失项、实际失败原因或未接受理由，同时提供恢复入口。不得静默改用旧宿主表达流程，也不得将起草、刷新或整篇重写误报为完成。不得提前刷新覆盖快照以表示正文已审阅。

交付时分别说明“外发表达步骤状态”与“宿主表达检查状态”：

- 外发表达步骤状态由脚本实际返回状态决定；
- 宿主表达检查状态应涵盖大纲审核、各节核收、全文语义核对、冷读、图文关系与硬禁项检查的实际范围。

候选已产出但未接受，整体仍未完成。只读审校仅按实际审阅范围报告，不伪称执行了拟稿流程。已核对且无需改写的部分可保留，完成依据为是否符合读者任务与事实，而非采纳数量。

纯渲染、`--check-project`、`--read-proof`、`--status`、`--refresh-coverage`、发布文档钩子、`check:release-docs`、setup、site-design、help、quickstart 自身及 `check-style.mjs` 均不向消费者的外部表达服务发起请求，也不通过这些操作修改文案。`npm run verify` 的业务检查同样不外发或改稿；其聚合测试采用隔离配置与本地 mock 调用表达脚本，不继承消费者的服务配置或凭据。quickstart 路由后的起草或刷新由目标技能执行拟稿流程。

0.6.0 版本已分发可配置脚本；本文描述的顺序拟稿主流程已随 0.6.1 正式发布并分发。各宿主是否已更新并加载该版本，仍需分别核验，不据此宣称宿主更新或加载验证已完成。

## 辅助检测器

```bash
node scripts/check-style.mjs 稿件.md 页面.html
```

检测器仅报告问题，不修改文件，也不联网。Markdown 检查普通正文；旧 HTML 仅抽取 `<main>` 内文本，排除导航、页脚、样式、脚本与代码区。硬禁项导致退出码为 1，输入错误退出码为 2，其余情况退出码为 0。句长、连词与长句警告用于定位问题，不按比例删词或制造长短差；是否修改由读者任务与事实决定。
