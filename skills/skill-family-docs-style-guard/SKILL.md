# 中文知识站正文审校

审校分为三道检查：先核对事实，再让目标读者冷读实际任务，最后清理表层表达。检测器退出 0 只表示没有命中确定性硬禁，不能代替事实核对或任务冷读。

## 一、事实检查

动笔前记录四项内容：目标读者与可假定的前置知识；读者要完成的动作或判断；代码、配置、公开接口、实测结果或权威说明等事实来源；不得改变的版本、路径、状态、条件和授权边界。

材料不足时缩短内容，不保留占位标记，也不用重复换句填满页面。版本号和标签使用 `public-release.json` 已声明的版本源，不在 Markdown 中复制可能漂移的数字。本地源版本不等于已发布或可安装版本。

## 二、理解检查

先选一条主要使用场景，从读者遇到的问题开始，沿同一条任务路径检查适用条件、必要输入、操作入口、成功结果和失败后的下一步。任务页需要的信息可以分散在自然段、列表和小标题中，不要求固定栏目。可复制提示词只在它确实是操作入口时提供；底层 npm API、完整字段表和退出码放到参考页，不阻塞普通任务的第一屏。

正文需要帮助读者定位故障或选择接入方式时，说明有关组件的职责、数据或控制怎样流动，以及限制为什么出现。架构解释必须能支持一个实际判断，例如正文事实写错时回到 Markdown 和事实来源，页面与正文不一致时检查渲染，是否已发布则查正式发布证据。只罗列目录、函数或组件名不算解释；来源不足时缩短内容。

冷读时只给读者目标页和已声明的前提。记录具体卡点：不知道输入什么、找不到执行入口、条件不明，或无法判断结果。“感觉不自然”不是可执行结论。

普通内容刷新只改变化影响的 Markdown。不改 `pages.json` 中的 ID、标题、分组、顺序和 `productKind`，不改模板或输出路径。若读者行为没有变化，保留正文并说明判断依据。

## 三、表达检查

起草或扩写前读取 `references/writing.md`。改稿、审校或发布前检查读取 `references/revision.md` 和 `references/readability.md`。围绕读者任务集中处理术语首次出现、商业黑话、占位水文和凭空结论，并结合上下文判断句长、连词和长句提示。

句长、连词和长句清单只用于定位可能的表层问题。是否修改以及怎样修改，都回到当前场景、读者任务和原始事实；不按比例删词，不为制造长短差补句，也不把改稿固定拆成多轮。

新格式的 Markdown 不写一级标题，因为页面 `title` 由 `pages.json` 统一生成。二至四级标题可以在末尾声明 `{#id}` 作为稳定锚点。提示词使用 `prompt` 代码块；备注只使用 `NOTE`、`TIP` 或 `WARNING` 类型。正文不输入原始 HTML、MDX、样式或脚本。

## 检测器

长篇 Markdown 或旧 HTML 页面可以运行：

```bash
node scripts/check-style.mjs 稿件.md 页面.html
```

检测器对 Markdown 按原文检查；对 HTML 只抽取 `<main>` 内的普通正文，排除导航、页脚、样式、脚本和代码区。硬禁命中退出 1，输入错误退出 2，其余退出 0。脚本只报告，不改稿件。

交付时说明事实来源、冷读卡点及修复、硬禁结果，以及判断后保留的警告。不把脚本退出 0 表述成“文章已经易读”。
