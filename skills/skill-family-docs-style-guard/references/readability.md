# 可读性门细则

可读性门回答一个问题：声明的目标读者，在允许的前置知识下，能不能不靠猜测读懂当前结论和下一步。本文件给出检查项和检测器的指标口径。

## 五类理解障碍

### 1. 术语无解释

系统字段、命令、代码标识符保留原文，但第一次出现时给中文语境。陌生术语高频出现就加短术语表，低频只在首现处就近解释。术语表不能代替正文逻辑：决定当前判断的术语，正文首次依赖时仍要说明它在这里的作用。

### 2. 概念解释得太晚

关键概念、裁决代码、状态名在第一次被依赖前解释。当前段依赖后文才定义的对象、先给输出后说用途、状态码已参与结论但含义未讲——出现任何一种就调整顺序。

### 3. 一句话承载多个主要判断

复杂关系允许长句，但一句只留一个主要判断。结论、原因、边界、后果同时出现时按语义节点拆开。不机械压成统一长度，也不连续堆短句。

### 4. 命令和字段缺少上下文

命令出现说明用途或预期结果，字段出现说明它表达的事实，代码块前后说明用途、输入、输出或原因。不用「以上代码展示了」敷衍。

### 5. 信息密度过高

一段同时切换多个产品、版本、状态或标识符时先拆层。读者要比较、计数、执行用列表；维度相同字段稳定用表格。长论证不塞进表格单元格。

## 检测器指标口径

`check-style.mjs` 统计层给出四个量化信号，允许误报，判断回到读者合同：

- **句长变异系数**（标准差 / 均值）：低于 0.42 提示句长过于整齐。人写的字长短差大，模型接近均匀。处理：挑几句压短，放开几句，不是全部改成中等长度。
- **连词密度**：「因为 / 所以 / 但是 / 然而 / 同时 / 此外 / 因此 / 不过 / 而且 / 并且」每千字个数，超过 7 提示可删一半。中文小句靠语序相接，连词是兜底不是默认。完整名单以 `check-style.mjs` 顶部词表为准。
- **长句率**：单句汉字数 ≥ 50 的句子占比。长句不自动判错，逐句检查是否扛着多个主要判断。
- **长句清单**：检测器列出所有超过 50 个汉字的句子和行号，供逐条人工核对。

## 不采用的机械规则

- 不要求每份文档都有术语表；
- 不固定「先读这段」式标题；
- 不要求一句只有一个主谓宾；
- 不要求三项并列一律列表化；
- 不把脚本退出码或统计分数当作可读性证明。
