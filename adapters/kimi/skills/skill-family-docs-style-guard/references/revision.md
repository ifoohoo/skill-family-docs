# 审校相位：改稿清单

本文件只在初稿完成后读。先按 `readability.md` 过完可读性门，再按下面的遍走。每一遍只做一件事，不合并。

## 第一遍　读者任务与开场

- 目标读者和前置知识是否明确；
- 开头是否快速说清文档性质、当前状态、主要结论和读者下一步；
- 标题和首段已经说清时，是否又多加了重复摘要区；
- 报告是否先给结论，教程是否先给场景和预期结果。

## 第二遍　认知负荷

对照 `readability.md` 的五类障碍逐个标：术语无解释、概念迟到、一句多判断、命令或字段缺语境、信息密度过高。处理原则：关键概念定义提前；一句只留一个主要判断；要比较、计数、执行的转列表；表格里的长论证搬回正文；一段切多个主题就拆层。

## 第三遍　删注水

给每段标一个作用：动作、事实、解释、例子、疑问、判断、背景，标不出来的就是注水。连续几段做同一件事，合并；后一段只是换个说法复述前段，删；某段删掉后结论纹丝不动，删。

## 第四遍　清 AI 腔

- **假深刻**：单独看漂亮、放回正文没增加事实或解释的句子，删；
- **假具体**：无来源的精确细节、编造的「用户反馈」，删；
- **名词化**：「进行了 / 实现了 / 起到了作用」还原成直接动词；
- **表演性排比**：同一句型连排三次以上，留两项，其余换说法或删；
- **借喻堆砌**：「底座 / 引擎 / 护城河」给抽象概念穿衣服的，还原成本义。

## 第五遍　听中文顺不顺

- 主干早点来：「……的，是……」句式先找做事的人放前面；
- 前后照应：突然换对象只靠「这 / 它」会认错人，把名字写回来；
- 停顿有轻重：读出声，逗号还能接、句号已落下；
- 动作少解释一句：动作本身已传出意思，不紧跟一句解释。

## 第六遍　硬禁清零

全文核查 SKILL.md 风格门的十一条硬禁和商业黑话名单，命中即改。改法：先找回这句话原本想说的事实，再用普通中文说出来，不找另一种漂亮句式替换。常见映射：

- 「你 / 您」→「开发者 / 用户 / 我们」或命令式；
- 「我认为」→ 删，让事实自己说话；
- 「如下所示」→「示例如下」或直指上文；
- 「综上所述」→ 删；
- 感叹号 → 句号，情绪词 → 中性事实。

## 第七遍　核事实与占位

- 逐项核对数字、版本、路径、状态、因果、限定词和授权边界，与原始材料一致；外部标准的定义引出处；
- 术语首现有解释，命令有用途，字段有含义；
- 占位清零：不留「待补充 / TODO」；确属草稿的统一标明并移出正式文档；
- 结尾若只是重新摘要全文，删，不强行升华。

## 用检测器

```bash
node ../scripts/check-style.mjs 稿件.md 页面.html
```

检测器把硬禁判为 failure，警告和统计供人工判断。HTML 输入只检查 `<main>` 正文，并保留原文件行号。它不能证明读者已经理解，也不能证明事实正确。别为了让警告变少而机械拆句、堆术语表或改标题——判断永远回到目标读者和原始材料。

## 最后冷读

忘掉规则，只答五个问题：只读标题和开头，知不知道文档要解决什么；哪一节必须回看前文才能懂；哪个概念用得比解释早；哪句话说得比材料大；版本、路径、状态、条件和权限是否仍与原文一致。
