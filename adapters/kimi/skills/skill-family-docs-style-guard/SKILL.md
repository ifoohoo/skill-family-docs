# 中文知识站拟稿与审校

起草、内容刷新或显式整篇重写时，先读取 `references/shared-writing-workflow.md` 执行公共拟稿与核收，再读取 `references/expression-service-config.md` 按真实脚本合同调用随技能分发的 `scripts/expression-outbound.mjs`。宿主负责组织材料、审核大纲、顺序核收各节和全文；模型只产出候选。只读审校可以定位事实、理解和表达问题，但不调用模型改稿，也不据此宣称拟稿流程已完成。

公共流程与配置以这两份参考为准，本入口不另维护一套独立规则。本入口继续执行知识站领域边界：公开材料筛选、页面身份、图文与格式、render-site 写回和覆盖。

## 本站材料与身份

读取 `references/writing.md`，看完本次文稿及直接事实来源。公共流程要求的角色、读者、阅读任务、事实清点与机器身份核对仍然执行。本站还须逐项核对页面 ID、URL 和已有稳定锚点。不得把 quickstart 改成 setup 等不同入口。本地源版本不等于已发布或可安装版本；站点版本仍从 `public-release.json` 已声明的来源取得。

普通内容刷新保留 `pages.json` 的 ID、标题、分组、顺序、`productKind`、模板和输出路径；判断读者行为没有变化且原文仍符合目标时保留原文，并说明核对依据。命令全集放参考页，任务页在真正需要时才引入。

发送前移除不在公开材料范围的内容。这是本入口的材料限制，不写入公共流程，也不要求其他消费者采用同一限制。

## 先审核大纲，再顺序拟稿

按 `references/shared-writing-workflow.md` 审核大纲并按完整语义单元顺序拟稿。从技能根目录运行脚本，输入、上下文与仓外候选路径遵循 `references/expression-service-config.md`。

首次外发前向用户说明发送目标；已有授权不逐次重复确认。凭据不进入文稿或上下文。

## 接受每节，再通读全文

读取 `references/revision.md` 与 `references/readability.md`。每节拟稿、集中修订、全文拼接、通读、图文核对和冷读按公共流程执行。

新格式的 Markdown 不写一级标题，页面 `title` 由 `pages.json` 生成。二至四级标题可在末尾声明 `{#id}` 稳定锚点；提示词使用 `prompt` 代码块，备注只用 `NOTE`、`TIP` 或 `WARNING`。正文不输入原始 HTML、MDX、样式或脚本。

完成上述核收后，由 render-site 的既有写路径把接受稿写入 `site.dir`；原稿与候选另存于指定文稿文件。不得提前刷新覆盖快照以表示正文已审阅。

## 完成与失败边界

缺配置、调用失败或候选未接受时，按公共流程保留原稿并报告“表达优化未完成”。不得静默改用旧宿主表达流程，也不得将起草、刷新或整篇重写误报为完成。

纯渲染、`--check-project`、`--read-proof`、`--status`、`--refresh-coverage`、发布文档钩子、`check:release-docs`、setup、site-design、help、quickstart 自身及 `check-style.mjs` 均不向消费者的外部表达服务发起请求，也不通过这些操作修改文案。`npm run verify` 的业务检查同样不外发或改稿；其聚合测试采用隔离配置与本地 mock 调用表达脚本，不继承消费者的服务配置或凭据。quickstart 路由后的起草或刷新由目标技能执行拟稿流程。

0.6.0 版本已分发可配置脚本；本文描述的顺序拟稿主流程已随 0.6.1 正式发布并分发。各宿主是否已更新并加载该版本，仍需分别核验，不据此宣称宿主更新或加载验证已完成。本入口提取的两份公共参考仍是本地候选，尚未随正式发布分发给外部消费者。

## 辅助检测器

```bash
node scripts/check-style.mjs 稿件.md 页面.html
```

检测器仅报告问题，不修改文件，也不联网。Markdown 检查普通正文；旧 HTML 仅抽取 `<main>` 内文本，排除导航、页脚、样式、脚本与代码区。硬禁项导致退出码为 1，输入错误退出码为 2，其余情况退出码为 0。句长、连词与长句警告用于定位问题，不按比例删词或制造长短差；是否修改由读者任务与事实决定。
