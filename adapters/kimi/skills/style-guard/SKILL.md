# 风格守卫：三道门

目标读者是人。先保证写的东西有事实撑腰，再让读者读得下去，最后清掉表层腔调。检测器退出 0 只代表没命中硬禁，不代表文档好读，更不代表事实正确。

## 使用方式

- **起草 / 扩写**：先读 `references/writing.md`，过完事实门再动笔。
- **改稿 / 审校 / 发布前自检**：读 `references/revision.md` 按遍走，配合 `references/readability.md` 做可读性检查。
- **量化自检**：长稿落盘成 Markdown 后运行：

```bash
node scripts/check-style.mjs 稿件.md [更多文件...]
```

检测器输出 failure（硬禁）、warning（人工判断）和统计指标；硬禁命中退出 1，输入错误退出 2，其余退出 0。它只报不改——改句子是人的活。

## 一、事实门

动笔前先把四件事写下来：目标读者和允许假定的前置知识；读者读完要能做成的判断或动作；支撑结论的材料；不得在改写中变化的版本、路径、状态、条件和授权边界。

材料门槛是硬约束：技术主题手里要有代码、配置、接口行为、错误现象、实测数据或权威出处。材料撑不起篇幅时，能查的先查，需要用户判断的一次问完，仍不够就缩短篇幅。禁止拿「待补充」「TODO」或换个说法复读来灌字数——缺材料的主题本来就不该开长篇。

结论必须有来路：材料支持七成就说七成，剩下的承认不知道。凭空断言和给规则编理由都在风格门硬禁之列，根子都在事实门。

## 二、可读性门

细则见 `references/readability.md`，检测器给出机械可见的部分。核心信号：

- **句长变异**：真人写字长短差很大。句长变异系数过低（检测器阈值 0.42）说明句子排得太整齐，挑几句压短，放开几句。
- **连词密度**：「因为 / 所以 / 但是 / 然而 / 同时 / 此外」每千字超过 7 个就该删一半，中文小句靠语序和事理相接。
- **长句率**：单句 50 个汉字以上要检查是否同时扛着结论、原因、边界和后果；一句只留一个主要判断，复杂关系允许长，但主干要先出来。
- **术语首现需解释**：命令、字段、状态码第一次出现时给中文语境；高频陌生术语多就加短术语表，少就就近解释，不倒背景。

这些是可读性的代理指标，不是验收结论。别为了压指标机械拆句。

## 三、风格门

硬禁清单（failure，必须清零才能交稿）：

1. **第二人称说教**：不用「你 / 您」直呼读者，以「开发者 / 用户 / 我们」代称；确指交互界面文案的除外。
2. **作者现身**：「我认为 / 我觉得 / 我建议」不出现在正文，以所写对象作主语。
3. **商业黑话**：赋能、抓手、闭环、拉通、底层逻辑、顶层设计、降本增效、全链路、组合拳、技术底座、认知增量一类，命中即改。技术专有名词（框架名、协议名）不在此列。
4. **表演性排比**：同一句型连排三次以上只为声势，留两项，第三项换说法或删。
5. **感叹号与情绪词**：正文不出现「！」；强大、优秀、完美、极致、业界领先这类评价词换成中性事实。
6. **「如下所示」**：改成「示例如下」「结构如下」，或直接指着上文说。
7. **凭空收束**：「总之 / 综上所述 / 换言之」开头凑结尾的，删。前文讲清了就不必再证明。
8. **占位注水**：「待补充 / TODO / 文档后补」不进交付稿。
9. **给规则编造理由**：约定本身即理由，不写说服式解释。
10. **凭空下结论**：外部标准的定义必须引出处，不自造。

警告层（warning，人工判断，不强制清零）：

- **翻案腔**：「不是 A，而是 B」先立一个没人持有的误解再推翻它。技术澄清「先陈述常见误解再纠正」是教学必要，保留。
- **名词化**：「进行了调整 / 实现了增长 / 起到了作用」还原成直接动词。
- **AI 抒情腔**：安放、抵达、微光、丰盈、滚烫、轻盈——给抽象概念穿衣服的全删，写具体事物时保留。
- **提示性冒号**：「下面是：」「核心是：」这类，节制使用。
- **段落开场重复**：相邻段落同一开场词反复出现。

冲突裁决：技术文档不禁冒号、不禁破折号、允许作者隐身，这些按「中文段用中文标点、代码用英文标点」处理，不在硬禁之列。

## 交付纪律

写作相位只交作品，不展示内部检查过程。审校相位说明：哪些句子改了、为什么改，哪些警告判断后保留。改违禁句时先找回它原本想说的事实，再用普通中文说出来，不拿另一种漂亮句式替换。
